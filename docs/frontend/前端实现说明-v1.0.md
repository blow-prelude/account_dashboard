## 2. 运行与数据源

```bash
uv run account-dashboard run
# 打开 http://127.0.0.1:8765/
```

前端产物存在时由 `api/static_mount.py` 自动挂载；不存在时整体跳过，不影响 API 调试。

### 2.1 三种数据源模式

| 模式 | 触发 | 行为 |
|------|------|------|
| `auto`（默认） | 无参数 | 探测 `/api/v1/health` 后，再探测 `/stats/overview`；**只有统计端点就绪才使用真实后端**，否则整体切到本地契约数据源 |
| `live` | `?mock=0` | 强制真实后端；C4 未交付时统计页会显示错误面板，导入页仍可用 C2 |
| `mock` | `?mock=1` | 强制本地契约数据源；`?mock=reset` 清空本地数据后重建 |

**为什么按整个应用而不是按端点降级**：导入写的是后端数据库，报表读的是统计接口；若一半真实一半演示，用户刚导入的流水不会出现在报表里，属于比"演示数据"更严重的误导。因此 C4 交付前保持整体一致，顶栏明确标注「演示数据」。

本地数据源不是静态 fixture：它按 §9 口径计算 KPI、分类、趋势、环比与摘要，并完整模拟 C2/C3 的状态机与幂等语义（重复确认 `E2002`、模板 `abort` `E2003`、预检只读、强制新增翻转为 `new`）。数据持久化在 `localStorage['fd-mock-v3']`，刷新不丢。

### 2.2 就绪探针的切换时机

C4 交付 `/stats/overview` 后，`auto` 模式自动切到真实后端，无需改代码。若只想先用真实 C2 调导入链路，用 `?mock=0#import`。

## 3. 契约消费规则（前端硬约束）

1. **统一信封**：所有响应按 `ApiResponse{code,data,message}` 解析；`code !== "OK"` 一律抛 `ApiError(code,message,status,detail)`，页面只用 `message` 与少数 `code` 分支，不解析 HTTP 文本。
2. **金额整数分**：前端只在 `core/format.js` 做 `cents / 100`；任何计算/提交都不出现 `float * 100`。阈值输入按"元"展示，提交前 `Math.round(元 × 100)`。
3. **时间无时区**：请求 `YYYY-MM-DDTHH:MM:SS`；展示层只做切片与本地解析，不做时区换算。
4. **周期锚点**：`month=YYYY-MM`、`quarter=YYYYQn`、`year=YYYY`；季度默认取**最近一个完整季度**（当前 10 月 → `2026Q3`）。
5. **分页**：`page ≥ 1`、`page_size ∈ [10,200]`；明细默认 20 条，导出最多 200 条。
6. **统计不做前端聚合**：KPI、分类占比、趋势、Top N、摘要全部来自后端；图表只接收已聚合序列。
7. **状态只读**：`status` 仅由后端写入；前端只发动作（编辑分类/备注、排除、重算、确认入库）。
8. **错误文案面向用户**：直接展示后端 `message`（已是中文可执行文案），技术细节只进控制台。

### 4.3 分类层级

PRD 附录 B 是两级：`支出 → 餐饮美食`。因此：

- `transaction.category_l1 = 支出/收入/资金流转`，`category_l2 = 餐饮美食/…`；
- 统计接口按 §9.4 过滤 `direction='expense'` 后再分组，`level=2` 的切片同时带 `l1/l2`；
- 前端展示"消费分类"时统一取 `slice.l2 || slice.l1`，不假设 `l1` 等于账簿的一级分组；
- 原型中的第三层（餐饮美食 → 外卖/食堂）**没有数据模型支撑**，分类分析页改为「消费分类 → 近 6 月走势 + 该分类流水」，保持下钻能力而不伪造层级。

### 4.4 用到的错误码

| code | 前端处理 |
|------|----------|
| `E1001/E1005` | 上传前/后提示格式与大小；不建批次 |
| `E1002/E1003/E1004` | 上传返回 `detail.batch_id` 时进入"解析失败"态，可重试/丢弃；不丢批次上下文 |
| `E1007` | 映射页阻止进入预检，标出缺失的硬三字段 |
| `E1008/E1010/E1011` | 参数/分页/路径错误，展示后端文案 |
| `E2002` | 重复确认、错误状态操作：提示当前状态，不重试 |
| `E2003` | 模板冲突：弹「覆盖 / 另存 / 取消」 |
| `E2006/E2007/E2008/E2009/E2010` | 分类、规则、设置、字段白名单、流水不存在 |
| `E4001/E4003/E4005/E4006/E4007` | 磁盘、删除、备份校验、恢复、回退 |
| `E5001` | 统一错误面板 + 重试入口 + 日志路径提示 |

## 5. 与原型/SDD 的有意差异

| 项 | 原型/SDD | 实现 | 原因 |
|----|----------|------|------|
| 技术栈 | SDD §6.6 的 React + 生成类型 | 原生 ES Modules + 手写契约客户端 | 原型本身零依赖、单进程静态挂载；引入构建链会新增工具链与产物同步成本。类型同步改由 `scripts/check-frontend.mjs` 守契约 |
| 报表对比图 | 独立的周期对比序列 | 复用 `/stats/trend` 的 `day/week/month` 分桶 | 契约没有 report 专用对比字段；避免前端二次聚合 |
| 导出 PDF | 后端生成 | `window.print()` + 打印样式 | 契约无 PDF 端点 |
| 备份"下载" | 下载导出文件 | 仅展示"仅供留存"，导出动作调用 `/backup/export` 生成文件 | 契约无文件下载端点 |
| 分类分析右栏 | 二级结构与迷你折线 | 近 6 月走势 + 该分类流水 | 无第三级分类模型 |
| 模板冲突 | `PUT /mapping` 409 | `POST /staging/templates` 显式 `policy` | C2 实际实现为 `save_template` 直接覆盖；显式落库更可控 |
| 设置项保存 | 主题也入库 | 主题只写 `localStorage`，其余走 `/settings` | 主题是设备偏好，SDD 设置白名单未含主题 |

## 6. 关键交互实现

- **导入五步**：状态由批次真实 `status` 驱动，刷新/关闭后可恢复；`uploaded→mapped_pending→prechecked→ingested` 与 D-1 一致；失败批次保留 `detail.batch_id`。
- **预检**：只读；`强制新增` 写 override 后重跑预检，行翻转为「新增 · 强制」；可撤销。
- **入库**：单次提交；`E2002` 提示"无需重复提交"；成功后展示 `monthly` 归档表与 `files_deleted`。
- **明细**：筛选/排序/分页全部走服务端；搜索 320ms 防抖并恢复焦点；汇总条与报表同源；批量归类可同时生成规则。
- **待确认**：按对方聚合，勾选组 → 批量归类；空态给出报表出口。
- **重算**：预览影响范围 → 二次确认 → 事务执行；`overwrite_manual` 默认关闭。
- **备份**：恢复前预检 → 输入「恢复」→ 自动生成回退点 → 失败可一键回退。
- **无障碍**：焦点可见、Esc 关闭弹层、状态三重编码（色/字/点）、`aria-sort`、`aria-modal`、`prefers-reduced-motion` 沿用原型。

## 8. 已知限制与后续

1. **C3/C4/C5 未交付**：确认入库、统计、报表、设置、备份、原始库在真实模式下仍为 404；`auto` 会使用本地数据源。C4 合并后自动切换。
2. **解析器适配器未注册**：真实 C2 的 `default_registry()` 目前没有微信/支付宝适配器，真实样例上传会 `E1003`；前端已正确处理失败批次。
3. **契约待冻结**：§4.2 的推定 DTO、§4.3 的 `l1/l2` 语义、`KpiDTO` 的两个环比字段、报表对比序列，建议在 C4 出口一并定版。
4. **无前端构建/类型生成**：若后续引入 Vite + TS，可用 `/api/openapi.json` 生成类型替换 `core/api.js` 的手写函数签名，页面代码不受影响。
5. **单机单用户假设**：无鉴权、无多标签页冲突处理；符合"仅监听 127.0.0.1"的部署约束。

## 9. 给后端的联调提示

- 前端只依赖 `/api/v1` 前缀与统一信封，不需要 CORS。
- 统计接口请保持"三个入口同源"：`/stats/*`、`/reports/*`、`/transactions/summary` 的数字必须相等；前端已按此做冒烟断言。
- 若 `KpiDTO` 不打算提供 `savings_mom` / `daily_avg_mom`，前端会显示「—」，无需改契约。
- `PendingGroupDTO` 若不含 `items[]`，待确认页只能显示组汇总，无法展开逐条；建议保留。
- `SettingsDTO` 的键名请与 §4.2 一致；前端按白名单收集后整批 `PUT`。
