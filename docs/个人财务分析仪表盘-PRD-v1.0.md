## 二、背景与目标

### 2.1 背景

用户为在校大学生，收入来源全部为父母转账与学校奖助学金等拨款，无理财投资习惯，资金平时放在零钱通、余额宝中获取日收益。近期感觉生活开销偏大，产生记账需求，并希望为将来理财打基础。用户已将全部流水导出为电子表格，希望以此为数据源制作月度 / 季度 / 年度财务报表，并通过前端网页仪表盘查看各报表板块。

用户已明确的部署与数据要求：

1. **本地使用，前后端分离**：前端网页与后端服务分离，整体部署在本机；
2. **缓冲区导入**：账单原始文件先导入「缓冲区」，经预览、映射、去重预检、确认后正式入库；
3. **按月归档**：确认后的原始流水按月份存入对应的原始数据库（raw 按月分表）；
4. **删除原文件**：原始数据成功入库后，删除缓冲区中的原始文件，不在磁盘留存敏感副本。

### 2.2 要解决的问题

| 编号 | 问题 | 现状 | 期望 |
|------|------|------|------|
| P-01 | 钱花在哪里说不清 | 只有原始流水表格，无结构 | 分类汇总一眼可见 |
| P-02 | 手工统计麻烦 | 每月在 Excel 里筛选求和 | 导入后自动出报表 |
| P-03 | 缺少周期性复盘 | 无月度/季度/年度视角 | 三个周期报表一键切换 |
| P-04 | 收支口径混乱 | 零钱通/余额宝申赎、父母转账混在流水中 | 明确「资金流转不计收支」口径 |
| P-05 | 原始文件管理无序 | 导出文件散落磁盘、重复导入难防 | 缓冲区暂存 → 按月归档 → 入库后删除 |
| P-06 | 为理财做准备 | 只看到零散余额 | 先建立结余与储蓄率认知 |

### 2.3 成功指标与口径

| 编号 | 指标 | 目标值 | 口径 / 验证方式 |
|------|------|--------|----------------|
| M-01 | 分类正确率 | ≥ 95% | 上线后抽检 20 笔，与人工核对一致的比例 |
| M-02 | 月度复盘耗时 | ≤ 5 分钟/月 | 从打开工具到看完月报；现状手工估算 > 30 分钟（估算值） |
| M-03 | 使用连续性 | 连续 4 周，每周导入 ≥ 1 次 | 导入批次记录 |
| M-04 | 储蓄率可见 | 每月自动产出 | 储蓄率 = 结余 ÷ 总收入（口径见第十章） |
| M-05 | 原始文件零残留 | 入库后缓冲区原文件删除率 100% | 扫描缓冲区目录，已入库批次不得残留文件 |

### 2.4 关键假设（可推翻）

- A-01：账单为支付平台/银行导出的 **CSV 或 Excel 文本文件**，非 PDF、非截图。
- A-02：以**单机、单用户、单账本**使用为主；前后端分离指架构分层，服务仅监听本机回环地址。
- A-03：全部金额为人民币（CNY），本期不做多币种。
- A-04：月流水约 80–200 笔、三年累计约 3,000–8,000 笔（估算，用于容量设计）。
- A-05：示例数据（人名、金额）均为虚构脱敏，仅用于说明。

## 三、名词与术语定义

| 术语 | 定义 |
|------|------|
| 流水 / 交易记录 | 一条收支明细，含时间、金额、方向、对方、商品说明等字段 |
| 收支方向 | 收入（income）/ 支出（expense）/ 中性（neutral） |
| 资金流转（不计收支） | 零钱通/余额宝申购赎回、信用卡还款、银行卡互转等资产形态转移，**不计入**收入与支出统计 |
| 缓冲区（staging） | 原始文件上传后的暂存区：文件落盘于本地缓冲区目录，完成预览/映射/预检，经用户确认入库或丢弃 |
| 导入批次 | 一次文件上传产生的记录集合，贯穿缓冲区到入库的全生命周期 |
| 原始库（raw，按月分表） | 按月份分表存储的原始流水归档（raw_YYYY_MM），保留导入原貌，只增不改，是审计与重算的基础 |
| 主数据层（transaction） | 经清洗、分类、可修正的分析数据层，仪表盘与报表的数据源 |
| 一级 / 二级分类 | 分类体系两级结构，如「支出 → 餐饮美食」 |
| 分类规则 | 关键词 + 匹配字段 + 目标分类的自动映射规则，含优先级 |
| 去重指纹 | 交易时间（秒级）+ 金额（分）+ 收支方向 + 交易对方 + 商品说明 的组合键，用于重复导入识别 |
| 待确认 | 未命中任何分类规则、需人工处理的流水状态 |
| 储蓄率 | 结余 ÷ 总收入 × 100% |
| 环比 | （本期 − 上期）÷ 上期 × 100% |
| 前后端分离 | 前端 SPA 与后端 REST API 为独立两层，通过 HTTP/JSON 通信，本地部署 |

## 四、需求范围

### 4.1 本期包含（In Scope）

**数据导入与归档**
- 文件上传至本地缓冲区（落盘暂存）、编码探测、解析预览
- 字段自动识别与手动映射（按来源渠道保存模板）
- 去重预检（入库前标注新增/重复，不直接污染数据）
- 确认入库：事务内写入原始库（按月分表）+ 主数据层，成功后删除缓冲区原始文件
- 缓冲区管理：批次列表、丢弃、重试、残留清理
- 原始库按月查看、按批次追溯、从原始库重算主数据层

**分类与分析**
- 自动分类（默认规则包 + 用户自定义规则）、手动/批量修正、历史重算
- 待确认队列集中处理
- 仪表盘：收支总览、分类占比、趋势、Top 商户
- 报表中心：月度 / 季度 / 年度报表，周期切换
- 流水明细：筛选、排序、单条编辑

**数据管理**
- 备份与恢复：数据库文件整体备份 + 全量导出双通道
- 分类体系管理（增改启停一级/二级分类）
- 基础设置：单日支出阈值、备份提醒间隔

### 4.2 本期不包含（Out of Scope，明确不做）

| 不做项 | 原因 | 去向 |
|--------|------|------|
| 自动同步银行 / 微信 / 支付宝数据 | 无面向个人的开放接口，且有授权与合规风险 | 后续版本池 |
| 理财收益记录、资产配置、投资建议 | 用户处于「先看清现状」阶段，避免范围蔓延 | 后续版本池 |
| 预算管理与超支提醒 | 依赖稳定分类数据，建议跑完一个账期后再做 | 后续版本池 |
| 多设备云同步 | 与隐私优先冲突，需单独方案 | 演进路径（见 5.3） |
| 多用户 / 家庭账本 | 单用户场景不需要 | 不做 |
| 多币种、发票识别、短信解析 | 超出核心闭环 | 不做 |
| 对局域网/公网开放访问 | 个人财务数据，仅限本机回环地址 | 禁止 |

## 五、方案对比与选型说明

### 5.1 候选方案对比

| 维度 | 纯前端本地版 | 本地前后端分离（**选定**） | 云端方案 |
|------|--------------|--------------------------|----------|
| 架构 | 浏览器内解析 + IndexedDB | 前端 SPA + 本地 REST 服务 + 本地数据库 | 前端 + 云服务器 + 云数据库 |
| 数据位置 | 浏览器存储 | 本机服务端与数据库文件 | 云端 |
| 隐私安全 | 最好 | 好（数据仍在本机，需防误暴露） | 差 |
| 文件生命周期管理 | 弱（无法可靠落盘/删除服务端文件） | **强**（缓冲区落盘、事务入库、确认后删文件） | 强 |
| 大数据量处理 | 受浏览器内存限制 | 服务端流式处理，容量只受磁盘限制 | 强 |
| 断网可用 | 是 | 是（服务在本机） | 否 |
| 工程化与扩展性 | 差 | 好（API 可复用，为后续云同步留基础） | 好 |
| 部署成本 | 零 | 低（本地一键启动） | 高 |

### 5.2 推荐结论

**选定「本地部署 + 前后端分离」**。理由：

1. 满足用户明确的两项硬性诉求——前后端分离的工程结构；原始文件经缓冲区落盘、按月入库、确认后删除，这一文件生命周期管理依赖服务端能力，纯前端方案无法可靠实现；
2. 数据仍全部留在本机（服务仅监听 127.0.0.1），隐私风险可控；
3. 服务端处理导入与重算，前端专注展示，容量只受磁盘限制；
4. 为后续「可选加密云同步」演进保留 API 基础。

### 5.3 演进路径（本期 → 后续 + 触发条件）

| 阶段 | 内容 | 触发条件 |
|------|------|----------|
| 本期 | 缓冲区导入 + 按月原始库 + 分类 + 仪表盘 + 三期报表 + 备份 | 立即启动 |
| 后续 v1.1 | 预算管理、超支提醒 | 连续使用 ≥ 1 个月且分类正确率 ≥ 95% |
| 后续 v1.2 | 多设备加密云同步（基于现有 API） | 确有两台以上设备高频使用需求 |
| 后续 v1.3 | 理财收益记录与资产总览 | 用户形成稳定结余并明确提出 |

技术栈为建议而非需求：前端 Vue 3 / React + Vite；后端 Node（Express/Nest）或 Python（FastAPI）；数据库 SQLite（单文件、零维护，个人场景首选）或本地 PostgreSQL；缓冲区为本地目录；通信 REST + JSON，文件上传 multipart/form-data。

### 6.1 用户画像（基于用户提供信息构建）

| 项目 | 内容 |
|------|------|
| 角色 | 小林（化名），在校大学生 |
| 收入结构 | 父母转账 + 学校奖助学金等拨款（虚构示例：月约 2,000 元） |
| 现状 | 无理财习惯，资金在零钱通/余额宝；近期感觉开销大 |
| 设备 | 手机为主，电脑偶尔；账单从手机导出后在电脑操作 |
| 环境 | 个人电脑本地部署，浏览器访问本机服务 |
| 痛点 | 不知道钱花在哪；Excel 手工统计麻烦；导出文件散落磁盘难管理 |
| 能力水平 | 非技术用户，能导出账单 CSV，不懂数据库与编程 |

### 6.2 用户故事与验收标准

**US-01 导入账单至缓冲区**
作为学生用户，我想要把账单文件先导入缓冲区，以便预览确认后再正式入库。
- Given 已导出一份账单 CSV；When 上传文件；Then 文件落入本地缓冲区并展示解析预览（前 20 行），此阶段不写入原始库与主数据层。

**US-02 字段映射**
作为学生用户，我想要自动识别表头并能手动校正，以便兼容不同平台的导出格式。
- Given 一份标准格式微信 CSV；When 进入映射；Then 交易时间/金额/方向/对方/商品五个核心字段自动命中；Given 表头含自定义列，When 手动调整并确认，Then 按映射正确解析。

**US-03 去重预检**
作为学生用户，我想要入库前看到哪些记录是重复的，以便放心确认。
- Given 导入一份与历史部分重复的文件；When 完成预检；Then 预览中逐条标注「新增/重复」，并给出汇总（新增 N 条、重复 M 条）。

**US-04 确认入库与按月归档**
作为学生用户，我想要确认后流水按月份归档到原始库，以便追溯与重算。
- Given 缓冲区中有一个待确认批次；When 点击「确认入库」；Then 原始流水按交易月份写入 raw_YYYY_MM 表，清洗分类后写入主数据层，并生成导入报告。

**US-05 原始文件自动删除**
作为学生用户，想要入库成功后自动删除缓冲区里的原始文件，以便不在磁盘留存敏感副本。
- Given 批次已确认入库成功；When 入库事务提交；Then 缓冲区中该原始文件被删除，扫描缓冲区目录无残留（M-05）。

**US-06 自动分类**
作为学生用户，我想要导入后自动分类，以便不用逐笔手工整理。
- Given 流水中存在对方为「美团外卖」的支出；When 导入完成；Then 该笔自动归入「支出 → 餐饮美食」。

**US-07 自定义规则与修正**
作为学生用户，想要为固定商户添加规则并修正误分类，以便报表越来越准。
- Given 待确认队列有 3 笔对方为「便利店」；When 批量设为「支出 → 购物消费」并勾选生成规则；Then 3 笔更新且后续同对方导入自动分类。

**US-08 查看月度报告**
作为学生用户，我想要查看月度财务报表，以便每月复盘一次。
- Given 本月已有入库流水；When 打开月度报表；Then 展示收支总览、分类占比、环比变化、Top 5 商户与文字摘要。

**US-09 周期报表切换**
作为学生用户，想要切换月度/季度/年度报表，以便从不同周期复盘。
- Given 库内有跨季度数据；When 切换报表周期；Then 各板块同步刷新，季度看环比、年度看同比（无上年数据时显示「—」）。

**US-10 导出备份**
作为学生用户，想要导出备份，以便防止数据丢失。
- Given 已使用一段时间；When 点击「导出备份」；Then 获得数据库整体备份文件；距上次备份超 7 天时页面提醒。

### 6.3 场景地图（用户旅程）

| 阶段 | 用户行为 | 痛点 / 机会点 |

## 七、功能需求

> 状态词约定：**必须（shall）/ 应该（should）/ 可以（may）/ 禁止（must not）**。每条需求有唯一编号，与 RTM（附录 A）对应。

### 7.1 导入与归档（缓冲区链路）

**FR-01 文件上传至缓冲区（Must）**
- 描述：用户上传账单文件，服务端将其写入本地缓冲区目录，生成导入批次，此阶段不写入任何业务表。
- 业务规则：
  1. 必须支持 CSV 与 Excel（.xlsx）；
  2. 单文件超过 5MB 或 50,000 行时必须提示分批；
  3. 文件必须落盘至本地缓冲区目录（非仅内存），刷新页面后批次不丢失；
  4. 必须自动探测 UTF-8 / GBK / GB18030 编码；
  5. 上传过程必须展示进度，中断后可重试；
  6. 禁止将文件上传至任何外部服务。
- 验收标准：
  - Given 一份 5,000 行的微信账单 CSV；When 上传；Then 文件出现在缓冲区目录，页面展示解析预览（前 20 行）；
  - Given 上传过程中关闭页面；When 重新打开；Then 该批次仍在缓冲区列表中，可继续解析或丢弃。

**FR-02 缓冲区解析与预览（Must）**
- 描述：对缓冲区文件执行编码探测、表头识别与内容解析，输出预览。
- 业务规则：
  1. 必须展示：识别到的字段列表、前 20 行数据、总行数；
  2. 解析失败（编码异常/结构损坏）必须给出明确原因，批次停留在缓冲区可重试；
  3. 禁止解析失败时产生任何数据库写入。
- 验收标准：
  - Given 一份 GBK 编码文件；When 解析；Then 中文正常显示无乱码；
  - Given 一份结构损坏文件；When 解析；Then 提示具体错误原因，原始库与主数据层无变化。

**FR-03 字段映射（Must）**
- 描述：自动识别表头并允许用户校正，映射模板按来源渠道保存复用。
- 业务规则：
  1. 必须自动识别核心字段：交易时间、金额、收支方向、交易对方、商品说明；
  2. 次要字段（交易类型、支付方式）应自动识别，失败置空而非阻断；
  3. 必须支持手动调整映射，并按渠道（微信/支付宝/银行卡）保存模板；
  4. 禁止未确认映射即入库。
- 验收标准：
  - Given 标准微信 CSV；When 进入映射；Then 五个核心字段全部自动命中；
  - Given 手动映射后确认；Then 预览数据按新映射刷新。

**FR-04 去重预检（Must）**
- 描述：入库前按去重指纹比对，逐条标注新增/重复。
- 业务规则：
  1. 必须按指纹（交易时间秒级 + 金额分 + 方向 + 对方 + 商品说明）比对库内记录；
  2. 预览中必须逐条标注「新增 / 重复」，并给出汇总计数；
  3. 同一天同金额不同对方的两笔，禁止误判为重复；
  4. 预检为只读操作，禁止此阶段写库。
- 验收标准：
  - Given 与历史部分重复的文件；When 完成预检；Then 汇总显示「新增 N 条 / 重复 M 条」，抽查标注准确；
  - Given 同一天同金额不同对方两笔；When 预检；Then 均标注「新增」。

**FR-05 确认入库与按月归档（Must）**
- 描述：用户确认后，在一个数据库事务内完成原始库按月写入与主数据层写入。
- 业务规则：
  1. 必须在一个事务内完成：①原始记录按交易月份写入对应 raw_YYYY_MM 表（保留导入原貌，含批次号与行号）②清洗分类后写入主数据层；
  2. 事务任何一步失败必须整体回滚，批次回到「待确认」，原始文件保留可重试；
  3. raw 表必须按交易时间所属自然月分表，无数据月份不建空表；
  4. 入库完成后必须生成导入报告：总行数 / 新增入库 / 跳过重复 / 待确认；
  5. 禁止部分成功状态（要么全成功，要么全回滚）。
- 验收标准：
  - Given 覆盖 3 个月流水的文件；When 确认入库；Then raw_2026_01、raw_2026_02、raw_2026_03 三表按月份正确归入对应记录；
  - Given 模拟入库写入失败；When 事务回滚；Then 原始库与主数据层均无该批次数据，批次可重新确认。

**FR-06 原始文件清理（Must）**
- 描述：入库事务提交成功后，删除缓冲区中的原始文件。
- 业务规则：
  1. 必须严格遵循「先入库成功，后删除文件」的顺序；
  2. 删除失败时必须记入「待清理列表」并可重试，不影响已入库数据；
  3. 用户丢弃批次时，同样必须删除对应缓冲区文件；
  4. 删除动作必须记录日志（批次号、文件路径、时间、结果）。
- 验收标准：
  - Given 批次入库成功；When 事务提交；Then 缓冲区目录中该文件被删除，扫描无残留；
  - Given 删除时文件被占用导致失败；When 失败；Then 批次显示「文件待清理」，数据不受影响，提供重试入口。

**FR-07 缓冲区管理（Must）**
- 描述：集中管理缓冲区批次与文件。
- 业务规则：
  1. 必须展示批次列表：文件名、渠道、状态、行数、上传时间、文件大小；
  2. 必须支持丢弃（二次确认，删文件）、失败重试；
  3. 应提供服务重启后的残留扫描：对无对应批次记录的孤儿文件提供一键清理；
  4. 缓冲区占用空间应展示，超过阈值（默认 500MB，可配）时提醒。
- 验收标准：
  - Given 缓冲区有 3 个批次；When 打开缓冲区页；Then 列表状态正确（待映射/待确认/已入库/已丢弃）；
  - Given 手动放入一个孤儿文件；When 点击残留扫描；Then 识别该文件并可一键清理。

**FR-08 原始库按月查看与重算（Should）**
- 描述：按月份查看原始归档，并支持从原始库重算主数据层。
- 业务规则：
  1. 应按月份展示 raw_YYYY_MM 的记录（只读）；
  2. 应按批次追溯：任一条主数据可回溯到来源批次与原始行；
  3. 应提供「按批次重算」：用原始库数据重新执行清洗与分类，执行前提示影响范围并二次确认；
  4. raw 数据禁止在主流程中修改。
- 验收标准：
  - Given 点击 2026-03 的原始库；Then 展示该月全部原始记录（含原始字段原貌）；
  - Given 修改了分类规则后对某批次重算；Then 主数据层按新规则更新并给出变更条数，raw 表不变。

### 7.2 分类与分析

**FR-09 自动分类（Must）**
- 描述：入库时按默认规则包与用户规则自动分类，未命中进入待确认。
- 业务规则：
  1. 必须内置默认规则包：美团/饿了么/外卖 → 餐饮美食；滴滴/地铁/公交 → 交通出行；零钱通/余额宝/理财 → 资金流转；信用卡还款 → 资金流转；
  2. 必须支持用户规则：关键词 + 匹配字段（对方/商品/交易类型）+ 目标分类 + 优先级；
  3. 命中多条规则按优先级取高，同级取最新创建；
  4. 未命中必须进入「待确认」，报表中单列「未分类」；
  5. 禁止把资金流转类默认计入支出统计。
- 验收标准：
  - Given 对方为「美团外卖」的支出；When 入库；Then 归入「支出 → 餐饮美食」；
  - Given 一笔「零钱通-转入」；When 入库；Then 归入「资金流转」，不计入收支统计。

**FR-10 手动/批量修正（Must）**
- 描述：在明细页与待确认队列修正分类，支持批量与规则生成。
- 业务规则：
  1. 必须支持单条修改分类；
  2. 应支持按对方名称批量套用（提示「将 XX 的 N 笔一并修改」，需确认）；
  3. 批量修正后应提供一键「生成规则」；
  4. 修正必须记录修改时间，可追溯。
- 验收标准：
  - Given 待确认队列 3 笔同对方「便利店」；When 批量设为购物消费并生成规则；Then 3 笔状态变为「已修正」，后续同对方自动分类。

**FR-11 分类规则管理（Must）**
- 描述：规则增删改查与启停，支持历史重算。
- 业务规则：
  1. 必须展示规则列表（关键词/字段/分类/优先级/启用状态）；
  2. 必须支持启停，停用后新导入不再套用；
  3. 应提供历史重算入口，执行前提示影响范围并二次确认，完成后给出变更条数。
- 验收标准：
  - Given 停用一条规则；When 重新导入含该关键词文件；Then 对应流水进入待确认；
  - Given 执行重算并确认；Then 历史流水更新并展示「更新 N 条」。

**FR-12 待确认队列（Must）**
- 描述：集中展示未分类流水。
- 业务规则：必须按对方名称聚合便于批量处理；处理完成必须展示空态；报表页存在待确认时必须显著提示数量。
- 验收标准：
  - Given 10 笔待确认；When 全部处理；Then 队列空态，月报「未分类」金额归零。

### 7.3 仪表盘与报表

**FR-13 收支总览仪表盘（Must）**
- 描述：一页看到周期内收支全貌，支持周期切换。
- 业务规则：
  1. 必须提供 KPI 卡：总收入、总支出、结余、储蓄率及环比；
  2. 必须提供收支趋势图（按日或按月，随周期自适应）；
  3. 必须提供分类支出占比图（环形图）；
  4. 应展示 Top 5 商户；
  5. 涨跌配色遵循国内习惯：不利变化（支出增加/结余减少）用红色，有利变化用绿色；
  6. 首屏应在 2 秒内（估算目标）渲染完成。
- 验收标准：
  - Given 本月有数据；When 打开仪表盘；Then 四张 KPI 卡与图表全部呈现；
  - Given 切换周期为「本季度」；Then 卡片与图表同步刷新为季度口径。

**FR-14 分类分析（Must）**
- 描述：按分类展示支出结构与变化，支持下钻。
- 业务规则：必须展示一级/二级分类金额、占比、环比；点击应下钻到明细；「未分类」必须单列。
- 验收标准：
  - Given 点击「餐饮美食」；Then 跳转明细页并带该分类筛选，汇总与报表一致。

**FR-15 趋势分析（Should）**
- 描述：按日/周观察支出曲线，标注异常日期。
- 业务规则：应提供每日曲线与每周汇总两种粒度；单日支出超阈值（默认 300 元，可改）应高亮；收入到账日应显著标记。
- 验收标准：
  - Given 某日支出 500 元超默认阈值；Then 该点高亮并悬浮提示；
  - Given 阈值改为 200 元；Then 超限判断按新阈值执行。

**FR-16 月度报表（Must）**
- 描述：月度财务报表，最高频使用。
- 内容：收支总览、分类结构表（金额/占比/环比）、Top 5 商户、日均支出、待确认提醒、自动文字摘要（3–5 条结论）。
- 验收标准：
  - Given 本月有完整数据；When 打开月报；Then 各板块汇总与明细页同口径核对一致；
  - Given 存在待确认；Then 报表顶部提示数量与处理入口。

**FR-17 季度报表（Must）**
- 描述：季度视角趋势与结构对比。
- 内容：季度内各月趋势对比、分类结构变化、季度结余与储蓄率、与上季度环比。
- 验收标准：Given 选择 Q2；Then 展示 4–6 月汇总与 Q1 环比。

**FR-18 年度报表（Must）**
- 描述：年度视角全年复盘。
- 内容：全年总览、12 个月收支对比、年度分类占比、年度储蓄率、同比（有上年数据时）。
- 验收标准：
  - Given 有两年数据；When 打开年报；Then 显示同比；仅一年时同比位显示「—」而非 0%。

**FR-19 流水明细查询（Must）**
- 描述：全量流水的表格化查询与编辑。
- 业务规则：
  1. 必须展示：时间、对方、商品说明、金额、方向、分类、支付方式、来源批次；
  2. 必须支持筛选：周期、分类、方向、支付方式、关键词；
  3. 必须支持按时间/金额排序；
  4. 筛选汇总必须与仪表盘同口径一致。
- 验收标准：
  - Given 筛选「餐饮 + 本月 + 支出」；Then 汇总金额等于月报餐饮分类金额。

### 7.4 数据管理

**FR-20 备份与恢复（Must）**
- 描述：数据备份与恢复，防止丢失。
- 业务规则：
  1. 必须支持数据库整体备份（SQLite 为文件拷贝；其他库为导出转储）；
  2. 必须支持全量 JSON/CSV 导出作为第二通道；
  3. 恢复时必须先预览将入库的记录数，二次确认后执行；
  4. 距上次备份超设定天数（默认 7 天）应提醒；
  5. 备份文件为本地文件，必须明示妥善保管。
- 验收标准：
  - Given 点击备份；Then 获得数据库备份文件；
  - Given 恢复到空库；Then 条数与各周期汇总与原库一致。

**FR-21 分类体系管理（Must）**
- 描述：维护一级/二级分类。
- 业务规则：必须内置预设体系（附录 B）；必须支持增改启停；停用已引用分类必须提示迁移（保留或迁到「其他」）；禁止无声删除被引用分类。
- 验收标准：
  - Given 新增二级分类「咖啡」；Then 选择器立即可见；
  - Given 停用被 20 笔引用的分类并确认迁移；Then 迁移完成。

**FR-22 基础设置（Should）**
- 描述：个性化偏好。
- 业务规则：应支持单日支出阈值、备份提醒间隔、每周起始日；仅 CNY，不做多币种。
- 验收标准：Given 阈值改为 200 元并保存；Then 趋势图与超限提示按新阈值生效。

## 九、业务流程与状态流转

### 9.1 文件生命周期（核心流程）

```
选择文件
  → 上传至缓冲区（服务端落盘，生成批次）
  → 编码探测与解析预览
  → 字段映射（自动识别/手动校正/保存模板）
  → 去重预检（逐条标注 新增/重复，只读）
  → 用户决策 ──┬─→ 确认入库 ──→ 数据库事务：
  │              │                  ① 原始流水按月份写入 raw_YYYY_MM（保留原貌+批次号+行号）
  │              │                  ② 清洗分类后写入主数据层 transaction
  │              │                  ③ 事务提交成功 → 删除缓冲区原始文件（失败则记待清理）
  │              │                  ④ 生成导入报告
  └─→ 丢弃批次 ──→ 删除缓冲区文件 → 批次状态=已丢弃
```

导入报告固定展示四个数字：总行数 / 新增入库 / 跳过重复 / 待确认。

### 9.2 导入批次状态机

| 状态 | 说明 | 允许操作 |
|------|------|----------|
| 待上传 | 未选择文件 | 上传 |
| 已上传（缓冲区） | 文件已落盘，未解析 | 解析、丢弃 |
| 待映射 | 解析成功 | 调整映射、确认映射 |
| 待确认 | 预检完成，已标注新增/重复 | 确认入库、丢弃 |
| 入库中 | 事务执行中 | 等待（锁定操作） |
| 已入库 | 事务成功，原文件已删 | 查看报告、查看跳过列表、按批次重算 |
| 已丢弃 | 用户放弃，文件已删 | 重新上传 |
| 失败 | 解析或入库失败 | 重试、丢弃 |

状态单向流转，禁止从「已入库」回退；丢弃必须二次确认。

### 9.3 原始库按月归档规则

- 按交易时间所属自然月分表：`raw_YYYY_MM`，如 2026 年 1 月流水写入 `raw_2026_01`；
- raw 表字段保留导入原貌（原始列 + batch_id + row_no + imported_at），**只增不改**；
- 无数据月份不建空表；跨月文件一次性入库时按月份拆分写入对应表；
- 主数据层与 raw 通过 batch_id + row_no 关联，任一条分析数据可回溯到原始行。

### 9.4 主数据层状态机

| 状态 | 说明 | 迁移条件 |
|------|------|----------|
| 待确认 | 未命中分类规则 | 分类处理后 |
| 已分类 | 自动规则命中 | 人工修正后 |
| 已修正 | 人工指定分类 | 可再次修正 |
| 已排除 | 用户标记不计收支 | 可恢复 |

### 9.5 资金流转不计收支规则（口径核心）

零钱通/余额宝申购赎回、信用卡还款、银行卡互转、提现默认为「中性（资金流转）」，**不计入**总收入/总支出；父母转账、奖助学金等**计入收入**；转账给个人默认不计支出，可改分类后计入。该口径必须在产品「帮助/说明」中明示。

## 十、数据与埋点需求

### 10.1 数据分层架构

| 层 | 载体 | 内容 | 写规则 |
|----|------|------|--------|
| 缓冲区 | 本地目录（文件）+ staging_batch 表 | 原始文件与批次元数据 | 上传写、确认/丢弃后删文件 |
| 原始库 | raw_YYYY_MM（按月分表） | 导入原貌流水 | 只增不改 |
| 主数据层 | transaction 表 | 分类后可修正的分析数据 | 可增可改 |
| 元数据 | rule / category / setting 表 | 规则、分类、设置 | 可增可改 |

### 10.2 核心实体与关键字段

**staging_batch（缓冲区批次）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 主键 |
| file_name / file_path / file_size | string / int | 缓冲区中的文件信息 |
| channel | enum | wechat / alipay / bank / other |
| status | enum | 待上传/已上传/待映射/待确认/入库中/已入库/已丢弃/失败 |
| total_rows / new_count / dup_count / pending_count | int | 预检与入库统计 |
| fail_reason | string | 失败原因（可空） |
| created_at / updated_at | datetime | 审计时间 |

**raw_YYYY_MM（原始库，按月分表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | integer | 主键 |
| batch_id | string | 来源批次 |
| row_no | integer | 文件内行号 |
| occurred_at | datetime | 交易时间 |
| amount_cents | integer | 金额（分） |
| direction | enum | income / expense / neutral |
| counterparty / item / txn_type | string | 原始字段 |
| channel | enum | 来源渠道 |
| imported_at | datetime | 入库时间 |

**transaction（主数据层）**：id、occurred_at、amount_cents、direction、category_l1、category_l2、counterparty、item、txn_type、channel、batch_id、row_no（关联 raw）、status（pending/confirmed/corrected/excluded）、note、created_at、updated_at。

**rule**：id、keyword、match_field、category_l1、category_l2、priority、enabled、created_at。
**category**：id、l1、l2、sort、enabled。
**setting**：key、value（单键值表，如单日阈值、备份提醒间隔）。

### 10.3 指标口径定义

| 指标 | 计算口径 | 边界说明 |
|------|----------|----------|
| 总收入 | 周期内 direction=income 的金额之和 | 不含 neutral |
| 总支出 | 周期内 direction=expense 的金额之和 | 不含 neutral |
| 结余 | 总收入 − 总支出 | — |
| 储蓄率 | 结余 ÷ 总收入 × 100% | 总收入为 0 时显示「—」 |
| 分类占比 | 该分类支出 ÷ 总支出 × 100% | 「未分类」单列 |
| 环比 | （本期 − 上期）÷ 上期 × 100% | 上期为 0 显示「新增」 |
| 日均支出 | 总支出 ÷ 周期自然日天数 | 按自然日 |

### 10.4 本地事件日志（可选，默认关闭）

本地可记录：导入成功率、待确认率、规则命中率、文件删除失败次数。**仅存本机，禁止上传**，设置中提供开关。

## 十一、权限与安全要求

1. 本期为单用户本机工具，不设账号体系；
2. 后端服务**仅绑定 127.0.0.1**，启动脚本与日志必须明示监听地址；禁止提供绑定 0.0.0.0 的选项，防止局域网暴露；
3. 缓冲区目录权限仅应用可读写；原始文件与数据库文件、备份文件均不得离开本机；
4. 删除原始文件必须以「入库事务成功」为前提，顺序不可颠倒；
5. 禁止提供「自动抓取银行/支付平台数据」功能，避免授权与合规风险；账单来源限于用户自行导出文件，遵守各平台服务条款（个人备份自用）；
6. 备份文件为本地文件，产品内必须明示「请妥善保管，勿上传公开平台」；
7. 文档与产品内出现的所有人名、账号、金额示例均为虚构脱敏数据。

## 十二、异常处理清单

| 编号 | 场景 | 触发条件 | 产品表现 | 恢复方式 |
|------|------|----------|----------|----------|
| EX-01 | 文件格式不支持 | 上传 .txt/.pdf/.jpg | 提示仅支持 CSV/Excel | 重新选择 |
| EX-02 | 编码探测失败 | 非常规编码 | 引导「另存为 UTF-8 CSV」 | 转换后重试 |
| EX-03 | 表头无法识别 | 自定义表头 | 进入手动映射，不阻断 | 完成映射继续 |
| EX-04 | 空文件 / 无有效行 | 0 数据行 | 提示无有效数据 | 检查导出文件 |
| EX-05 | 超大文件 | >5MB 或 >5 万行 | 提示分批 | 拆分导入 |
| EX-06 | 金额解析失败 | 含「¥」「,」等符号 | 自动清洗；仍失败置待确认并标注 | 明细页修正 |
| EX-07 | 时间格式异常 | 非标准格式 | 识别常见格式；失败置待确认 | 明细页修正 |
| EX-08 | 重复导入 | 指纹命中 | 预检标注重复，入库时跳过并报告 | 查看跳过列表 |
| EX-09 | 全量重复 | 全部记录已入库 | 提示「未发现新流水」 | 换新导出文件 |
| EX-10 | 入库事务失败 | 写入异常/磁盘满 | 事务回滚，批次回「待确认」，原文件保留 | 重试或丢弃 |
| EX-11 | 原始文件删除失败 | 文件被占用/权限 | 批次标记「文件待清理」，数据不受影响 | 清理列表重试 |
| EX-12 | 服务重启缓冲区恢复 | 导入中重启 | 批次停留在中断前状态 | 重新解析或确认 |
| EX-13 | 缓冲区残留孤儿文件 | 异常退出产生无批次文件 | 启动扫描 + 手动一键清理 | 确认后清理 |
| EX-14 | 存在待确认 | 未命中规则流水 | 报告与报表提示数量 | 队列处理 |
| EX-15 | 数据库损坏/丢失 | 文件误删/磁盘故障 | 引导从备份恢复 | 恢复备份（引导每周备份） |
