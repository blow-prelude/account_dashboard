## 3. 设置域

### 3.1 键与校验（照 SDD §11.3）

| 键 | 类型 | 默认 | 校验 | 失败文案 |
|----|------|------|------|----------|
| `daily_expense_threshold_cents` | int | 30000 | `0 < v ≤ 10_000_000` | 单日支出阈值必须大于 0 |
| `backup_reminder_days` | int | 7 | `1 ≤ v ≤ 365` | 备份提醒间隔需在 1~365 天之间 |
| `week_start` | int | 1 | `1 ≤ v ≤ 7` | 每周起始日需在 1~7 之间 |
| `buffer_size_threshold_mb` | int | 500 | `v ≥ 10` | 缓冲区阈值不得小于 10MB |
| `event_log_enabled` | bool | false | — | — |
| `data_dir_display` | str | 空 | **只读**，由引导配置回填 | 该值由配置文件决定，不可在此修改 |

### 3.2 两个坑

1. **`data_dir_display` 是镜像，不是配置源**。真正的 `data_dir` 在 `app.toml`。若允许 `PUT /settings` 改它，会出现"界面显示 A、实际写 B"的分裂。因此它必须出现在 `GET` 的响应里、但不在 `PUT` 的白名单里（422）。
2. **`week_start` 影响趋势分桶**。改它之后，季内按周的趋势会变。C5.1 的实现只需存值，但要在 `CONTRACT-CHANGELOG.md` 里记一句"`week_start` 变更影响 `/stats/trend?granularity=week` 的桶边界"，避免联调时被当成 bug。

## 4. 备份 / 恢复 / 回退

### 4.1 备份三步（顺序决定可用性）

```python
def create_db_backup(note: str | None) -> BackupDTO:
    conn.execute("PRAGMA wal_checkpoint(TRUNCATE)")     # ① 把 WAL 落盘，否则备份丢最近写入
    dst = backups_dir / f"ledger-{ts}.db"
    shutil.copy2(db_file, dst)                          # ② 冷拷贝（单用户、已 checkpoint）
    verify = integrity_check(dst)                       # ③ 立刻自检，不把坏备份当成功
    backup_repo.insert(kind="db", file_path=dst, size_bytes=dst.stat().st_size)
```

- 不做热备份（`VACUUM INTO` 也可，但对 15k 行没必要）；
- 备份文件命名带秒级时间戳，避免同秒覆盖；
- 备份成功后写 `setting.last_backup_at`（`GET /backup` 的过期判断依赖它）。

### 4.2 恢复：先备份再替换

```
① 预检：文件存在 → SQLite 头校验 → PRAGMA integrity_check → schema_version 兼容
② 自动备份当前库（pre_backup_id），失败则中止恢复
③ 关闭当前连接（WAL checkpoint + close）
④ os.replace(备份文件副本, db_file)
⑤ 重开连接 → 迁移（若备份版本旧）→ 校验条数
⑥ 失败 → 用 pre_backup 回滚，返回 E4006
```

三条底线：

- **预检不过绝不替换**（I-BK-02：损坏备份 → `E4005`，且**未发生任何文件替换**）；
- **恢复前必须有 pre_backup**，否则"恢复错了"没有退路；
- 恢复后必须重跑统计，条数与各周期汇总对齐（`test_backup_restore.py`）。

### 4.3 回退

`POST /backup/restore/rollback {pre_backup_id}` 就是"用 pre_backup 再恢复一次"。不要另写一套逻辑 —— 复用 `restore`，只是把 `pre_backup` 换成目标。

### 4.4 导出（第二通道）

`POST /backup/export {format: json|csv}`：全量 `transaction` + `category` + `rule`，金额以**元**为单位、两位小数（导出给人看，不是给程序读；导入侧不存在，因此不受 I4 约束）。

> 导出文件落 `data/backups/export-<ts>.<ext>`，返回 `{file_name, path, rows}`。**不提供导入**：本期数据入口只有账单文件（PRD 范围）。

## 5. 数据目录迁移

```python
def migrate(to_path: str, *, confirm: bool, copy_only: bool = False) -> MigrationResultDTO:
    # ① validate_data_dir(to_path)      → 非法 E1011
    # ② 非同一路径（resolve 后比较）      → 相同 E1011
    # ③ 磁盘余量 ≥ 当前 data_dir 大小 × 2
    # ④ 停写：置 maintenance 标志（迁移期间业务端点返回 503 或排队）
    # ⑤ 复制 db（checkpoint 后）+ buffer + backups
    # ⑥ 校验：条数、文件数、schema_version
    # ⑦ 写 app.toml 的 data_dir（copy_only=True 时跳过）
    # ⑧ 提示「请重启服务」
```

- **旧目录保留**，不删。用户的财务数据不能因为一次迁移就消失；清理由用户在确认无误后手动做。
- 迁移期间必须**停写**，否则复制过程中新写入会丢。实现上用一把 `maintenance_lock`，业务路由进入时检查。
- `copy_only=true` 用于"只想备份到另一块盘"的场景。

```bash
uv run account-dashboard export-openapi --out docs/api/openapi.json
```

验收：连导两次 `sha256` 一致（说明无随机顺序、无时间戳字段）；`ApiResponse[...]` 泛型在 schema 里展开为具体类型，不出现 `additionalProperties: true` 的空壳。

### 7.2 前端类型生成（对接点，不含前端实现）


本周期只需保证：命令能跑通、生成的 `generated.ts` 无语法错误、DTO 字段名与 `models/*` 一致。前端页面另行排期，但**联调前必须完成一次生成**，否则契约漂移无人发现。

## 10. 风险与回退

| 风险 | 表现 | 处理 |
|------|------|------|
| 备份时 WAL 未落盘 | 恢复后丢最近几条 | 备份前强制 `wal_checkpoint(TRUNCATE)`，并在用例里断言"写入后立即备份，恢复后条数一致" |
| 恢复过程中服务仍在写 | 恢复后数据错乱 | 恢复与迁移共用 `maintenance_lock`，业务端点 503 |
| 迁移时新目录被占 | 复制中断 | 先写 `.migrating` 标记，失败清理半成品，旧目录不动 |
| 事件日志膨胀 | 表越来越大 | 保留最近 90 天（启动对账时清理），或按条数上限 10 万 |
| 打包漏 `migrations/` | 新机 `init-db` 报找不到 V001 | wheel 校验清单里显式断言 `migrations/V001__init.sql` 存在 |

**回退策略**：C5 本身是"兜底能力"的周期，它自己出错时靠 `git revert` + 手动保留 `data/`。因此 C5 的所有变更**不得触碰** `V001` 与已冻结 DTO；需要加字段只能新增 `V002__*.sql`。
